## Результаты наблюдений (strace)
В ходе работы выполнялись команды `ls`, `file_demo.py`, `read_demo.py`, `process_demo.py`. 
Пример фрагмента трассировки открытия файла:
`openat(AT_FDCWD, "data.txt", O_RDONLY) = 3`
Это означает, что программа попросила ядро открыть файл `data.txt` только для чтения, и ядро вернуло файловый дескриптор 3.

## Объяснение основных системных вызовов
* `openat()` — открывает файл и возвращает его файловый дескриптор.
* `read()` — читает данные из файла в память программы.
* `write()` — записывает данные из программы в файл.
* `close()` — закрывает файл и освобождает дескриптор.
* `vfork()/clone()` — создает дочерний процесс.
* `execve()` — запускает новую программу в созданном процессе.
* `wait4()` — заставляет родительский процесс ждать завершения дочернего.

## Контрольные вопросы
1. Системный вызов — это просьба программы к ядру ОС выполнить действие.
2. Файловый дескриптор — это число (номер), выданное ядром для доступа к открытому файлу.
3. `openat()` открывает файл и выдает дескриптор.
4. `read()` читает данные, `write()` записывает их.
5. `write(3, "Hello", 5) = 5` означает, что ядро успешно записало 5 байт в дескриптор 3.
6. После `close()` дескриптор уничтожается, обращаться к нему нельзя.
7. `strace` нужен для отслеживания системных вызовов программы.
8. Запись большим блоком эффективнее, так как уменьшает количество переключений между программой и ядром.
